# 2026-09-29 Windows 自動覆蓋更新

狀態：功能完成，分支 `codex/windows-self-update`，尚未發版。

## 做法

- App 執行中，Windows 不允許覆蓋它的 exe 與 DLL（實測：執行中的 `flutter_windows.dll` 可以改名，覆蓋被拒）。所以分成兩段：App 下載並驗證新版，然後交給 PowerShell 更新腳本，App 自行結束；腳本等 App 結束後替換檔案，再重新開啟。
- 下載：放在 `%TEMP%\ZAI-X-update`。斷線，或 30 秒收不到資料時，用 HTTP Range 從已收到的位置接著下載，最多 6 次；伺服器不支援 Range 就從頭下載。重試期間進度框顯示「網路不穩，正在重新連線」。
- 驗證：大小與 SHA-256 必須和 GitHub Release 公布的 digest 一致。解壓時拒絕跳出暫存資料夾的條目，任何檔案寫不完整就失敗；必須有 `ZAI-X.exe`、`flutter_windows.dll`、`data/app.so`、`data/icudtl.dat`；腳本替換前再核對 exe 的版本號。
- 替換：舊檔先移到安裝資料夾的 `.update-backup`，新檔全部複製成功才刪除備份；任何一步失敗都把舊檔搬回原位、開啟原版本。只替換套件內的檔案，資料夾裡的其他檔案不動；使用者資料在 `%APPDATA%`，不受影響。
- 結果：腳本寫下結果（含安裝資料夾），新版啟動時提示「已更新到 vX」或「更新沒有完成，已保留原來的版本」。暫存資料夾是所有安裝共用的，只接受同一安裝資料夾的結果；成功但版本和目前執行的不同就視為過時，不顯示。
- 退回原本流程（下載 zip 後在檔案總管選取）：開發版、安裝位置無法寫入（例如 `C:\Program Files`）、Release 沒有 digest。下載重試用完則改用瀏覽器下載。
- 2.1.0 以前的版本沒有這套流程，所以第一次升到含此功能的版本，仍須手動解壓覆蓋一次。

## 過程中發現並修正

- 用 detached 模式啟動 PowerShell 5.1 時，它沒有主控台，腳本根本不會執行（英文路徑和中文路徑都一樣）。改用一般模式；從 GUI 程式啟動時，主控台同樣不會顯示。
- 進度框標題在深色主題看不見：外層彈窗的預設文字是深色，和卡片的對比只有 1.2。標題改用 App 主題的樣式，並用對比度測試涵蓋深、淺兩種主題；拿掉樣式時，深色主題的測試會以 1.20 失敗。
- 實際測試時，第一次按更新，下載到一半中斷，照原本的設計直接改開瀏覽器下載。因此加上續傳與重試。
- 另一份安裝啟動時，讀到別人留下的「已更新到 v2.1.0」並把結果刪掉。改成比對安裝資料夾與版本。
